# Subagent Generator - Subagent 生成规范

指导 Claude 如何正确创建和使用 subagent 的决策指南。

## 什么时候用 Subagent

满足以下条件时，优先考虑 subagent:

| 条件 | 说明 | 示例 |
|------|------|------|
| 可并行 | 多个任务互不依赖 | 搜索多个关键词 |
| 需隔离 | 任务可能失败或修改文件 | 并行测试、代码修改 |
| 上下文独立 | 不需要完整对话历史 | 资料收集、代码审查 |
| 结果可聚合 | 最终需要合并结果 | 多维度分析 |

**不用 subagent 的情况**:
- 单步操作（直接用工具即可）
- 需要完整对话上下文
- 任务间有强依赖

## Subagent 类型选择

```
用户请求
    ↓
需要探索代码库？ ──Yes──→ Explore 类型
    ↓ No
需要代码审查？ ──Yes──→ code-reviewer 类型
    ↓ No
需要修改文件？ ──Yes──→ general-purpose + worktree 隔离
    ↓ No
general-purpose（默认）
```

### 类型速查

| 类型 | 何时用 | 典型场景 |
|------|--------|----------|
| `general-purpose` | 大多数情况 | 搜索、收集、分析 |
| `Explore` | 快速查找代码 | 定位函数、理解结构 |
| `code-reviewer` | 审查代码 | 质量检查、安全扫描 |

## 参数配置决策

### 必需参数

```
Agent(
  description: "做什么（3-5 词，如'搜索 React 教程'）",
  prompt: "详细任务描述..."
)
```

**description 要求**:
- 简短明确，3-5 个词
- 说明任务类型（搜索/审查/分析）
- 便于在进度树中识别

### 可选参数决策树

```
需要特定模型？ ──Yes──→ model: "sonnet"|"opus"|"haiku"|"fable"
    ↓ No
需要深度思考？ ──Yes──→ effort: "high"|"xhigh"|"max"
    ↓ No
需要修改文件？ ──Yes──→ isolation: "worktree"
    ↓ No
需要后台运行？ ──Yes──→ run_in_background: true
    ↓ No
使用默认参数
```

### 模型选择指南

| 模型 | 用它当... | 成本 |
|------|-----------|------|
| `sonnet` | 默认选择，大多数任务 | 中等 |
| `haiku` | 简单搜索、格式化、快速响应 | 最低 |
| `opus` | 复杂推理、关键决策、代码生成 | 较高 |
| `fable` | 创意内容、文案撰写 | 中等 |

### Effort 级别选择

| 级别 | 用它当... |
|------|-----------|
| `low` | 简单搜索、格式转换、固定任务 |
| `medium` | 一般任务（默认推荐） |
| `high` | 复杂分析、需要推理 |
| `xhigh` | 高难度问题、关键决策 |
| `max` | 极端复杂、需要最大推理能力 |

## Prompt 设计原则

### 核心原则

1. **明确任务边界**: 一个 subagent 只做一件事
2. **结构化输出**: 要求 JSON 或固定格式，便于聚合
3. **约束字数**: 避免返回过多内容污染主上下文
4. **说明失败处理**: 告诉 subagent 遇到问题怎么办

### 通用 Prompt 模板

```
你是{角色}助手。

## 任务
{一句话说明要做什么}

## 输入
{提供的信息/关键词/文件}

## 返回格式
{明确的输出结构，如 JSON 或 Markdown}

## 约束
- 每条结果不超过 {N} 字
- 只返回 {需要的内容}，不要返回 {不要的内容}
- 如果找不到，返回空结果而非编造
```

### 资料收集 Prompt

```
你是一个资料收集助手。搜索关于 {主题} 的资料。

搜索关键词: {关键词}
信源偏好: {官方文档/博客/社区}

返回格式（严格遵守，每条不超过 150 字）:
- **标题**: [标题]
- **URL**: [链接]
- **摘要**: [核心观点]
- **相关性**: [1-5]
- **来源**: [官方文档/博客/社区]

禁止返回: 完整段落、导航、广告、Cookie 提示。

目标: 快速了解这类资料有哪些方向。
```

### 代码审查 Prompt

```
你是一个代码审查专家。审查以下变更:

## 变更文件
{文件列表或路径}

## 审查维度
- 代码质量
- 安全风险
- 性能问题

## 返回格式（JSON）
{
  "findings": [
    {
      "severity": "high|medium|low",
      "file": "路径",
      "line": 行号,
      "description": "问题描述",
      "suggestion": "修复建议"
    }
  ],
  "summary": "总体评价"
}

只报告真正的问题，不要列出"代码看起来不错"之类的无用信息。
```

### 代码探索 Prompt

```
你是一个代码探索助手。在代码库中查找: {目标}

查找范围: {目录/文件类型}
查找目标: {函数名/类名/模式}

返回格式:
- 文件路径
- 行号范围
- 简要说明（一句话）

只返回精确匹配结果，不要返回"可能相关"的内容。
```

## 并行执行模式

### 模式 1: 多路搜索（最常用）

**场景**: 搜索多个关键词，聚合结果

**执行方式**:
```
同时派发 3-5 个 subagent:
  Agent(description: "搜索 A", prompt: "...关键词 A...")
  Agent(description: "搜索 B", prompt: "...关键词 B...")
  Agent(description: "搜索 C", prompt: "...关键词 C...")

等待所有完成 → 聚合结果 → 按相关性排序
```

**注意**: 每个 subagent 返回结构化摘要（<150 字），不要返回原始内容。

### 模式 2: 两阶段收集

**场景**: 先粗筛，再精读

**执行方式**:
```
Phase 1（并行粗筛）:
  3-5 个 subagent 同时搜索不同角度
  每个返回: 标题 + 摘要 + 评分

Phase 2（定向精读）:
  筛选评分 ≥4 的资料
  用 WebFetch 深度阅读
  提取核心观点
```

### 模式 3: 多维度审查

**场景**: 从不同角度审查同一内容

**执行方式**:
```
同时派发:
  Agent(description: "审查代码质量", ...)
  Agent(description: "检查安全风险", ...)
  Agent(description: "分析性能问题", ...)

等待所有完成 → 合并发现 → 去重
```

### 并发控制

- 同时最多 5 个 subagent
- 超过 5 个时，分批执行
- 每批等待完成后再启动下一批

## 错误处理

### 常见错误及处理

| 错误 | 原因 | 处理 |
|------|------|------|
| 返回空结果 | 搜索无匹配 | 调整关键词重试 |
| 格式不符 | 未按要求输出 | 在 prompt 中强调格式 |
| 超时 | 任务太复杂 | 拆分任务或降低 effort |
| 内容过多 | 未约束字数 | 明确字数限制 |

### 容错设计

1. **检查返回值**: subagent 可能返回 null 或空
2. **部分失败可接受**: 3 个 subagent 中 1 个失败，用另外 2 个的结果
3. **降级方案**: 如果 subagent 全部失败，回退到直接用工具

## 输出格式选择

| 场景 | 推荐格式 | 原因 |
|------|----------|------|
| 资料收集 | Markdown 表格 | 便于人类阅读 |
| 代码审查 | JSON | 便于程序处理 |
| 多结果聚合 | JSON Array | 便于排序和过滤 |
| 简单列表 | 纯文本 | 最轻量 |

## 快速决策表

| 我想... | 怎么做 |
|---------|--------|
| 搜索多个关键词 | 3-5 个 general-purpose subagent 并行 |
| 审查代码 | 1 个 code-reviewer 或 3 个不同维度的审查 |
| 探索代码库 | 1 个 Explore subagent |
| 收集资料 | 两阶段：粗筛 → 精读 |
| 修改多个文件 | 每个文件一个 subagent + worktree 隔离 |
| 做复杂分析 | 1 个 opus + high effort |

## 注意事项

1. **description 要具体**: "搜索 React 教程" 比 "搜索资料" 好
2. **prompt 要约束输出**: 明确说"每条不超过 150 字"
3. **检查返回值**: subagent 可能失败或返回空
4. **控制并发**: 最多 5 个同时运行
5. **选择合适模型**: 简单任务用 haiku，复杂任务用 opus
6. **及时清理**: 使用 worktree 时，完成后清理
