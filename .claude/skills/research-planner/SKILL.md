# Research Planner - 资料收集需求规划器

在正式收集资料前，通过轻量级需求澄清和探测式引导，帮助用户明确方向，避免无效收集。

## 触发条件

当用户提出以下类型的请求时，调用此技能:

- "我想学一下 XX"
- "帮我整理一下 XX 的资料"
- "研究一下 XX"
- "了解一下 XX"
- "不知道从哪开始"
- "XX 相关的有什么"
- 任何意图模糊、未明确方向的研究请求

## 核心原则

### 1. 不替用户做决定，但帮用户看清选项

用户说"不知道"时，不是真的没想法，而是信息不足做不了决定。探测式收集就是给用户补充决策信息。

### 2. 每个阶段的输出都是下一阶段的决策点

不要在阶段 0 就决定阶段 3 的细节。每个阶段只锁定下一步需要的信息。

### 3. 学习笔记的特殊性：需要"渐进式"而非"一次到位"

和写一篇固定主题的文章不同，学习笔记往往在收集过程中会发现新的兴趣点。流程要允许中途调整方向。

## 工作流程

### Step 1: 轻量级需求澄清（仅需一次交互）

根据用户输入的信息量，决定提问的深度:

#### 场景 A: 用户信息充足

当用户已经明确说了类似:
- "帮我写一篇关于 React 18 并发模式的实战笔记"
- "整理 Kubernetes 部署最佳实践的入门教程"

→ **跳过提问**，直接进入 Step 2

#### 场景 B: 用户信息模糊

当用户只说了:
- "我想学 Rust"
- "帮我整理一下 AI Agent 的资料"
- "研究一下微服务"

→ **进入轻量级提问**，只问 3 个核心问题:

---

**📋 需求澄清**

在开始收集资料前，我想确认几个方向:

**问题 1: 你的笔记类型是？**
| 选项 | 说明 |
|------|------|
| 🛠️ 实战笔记 | 侧重代码示例、动手实践、项目案例 |
| 📖 概念学习 | 侧重原理讲解、知识体系、核心概念 |
| 💡 心得总结 | 侧重对比分析、踩坑经验、最佳实践 |

**问题 2: 你期望的学习深度是？**
| 选项 | 说明 |
|------|------|
| 🌱 入门了解 | 快速知道是什么、能做什么、怎么开始 |
| 🌿 能上手做 | 理解核心概念，能独立完成小项目 |
| 🌳 能讲给别人听 | 深入理解原理，能回答"为什么" |

**问题 3: 你的现有基础是？**
| 选项 | 说明 |
|------|------|
| 🆕 零基础 | 完全没接触过 |
| 📚 有一定了解 | 看过一些文章/文档 |
| 🔧 比较熟悉 | 已经用过一段时间，想深入 |

---

#### 场景 C: 用户明确表示"不知道"

→ **跳过提问**，直接进入 Step 2（探测式引导）

### Step 2: 探测式引导（对模糊意图）

当用户意图模糊时，用最低成本"探测"，帮用户"看见全景"。

#### Phase 1: 低成本探测

派 2-3 个 subagent，每个只搜一个角度，**只返回标题 + 一句话摘要**:

```
Subagent 1: 搜索 "{主题} 入门 教程"
Subagent 2: 搜索 "{主题} 实战 案例"
Subagent 3: 搜索 "{主题} 进阶 最佳实践"
```

每个 subagent 的 prompt:
```
你是一个资料探测助手。请搜索关于 {主题} 的资料，但只做初步探测。

搜索关键词: {关键词}

返回格式（严格遵守，每条只返回一行）:
- [标题] — [一句话摘要，30字内]

每个角度返回 3-5 条。不要返回 URL，不要返回详细内容。

目标: 快速了解这类资料大致有哪些方向。
```

#### Phase 2: 展示"方向菜单"

把探测结果整理成几个可选方向:

---

**🔍 探测结果**

关于 **"{主题}"**，资料大致分为这几个方向:

**方向 1: 🛠️ 实战路线**
- [标题 A] — [一句话说明]
- [标题 B] — [一句话说明]
- 适合: 想动手写代码、做项目的人

**方向 2: 📖 概念深入**
- [标题 C] — [一句话说明]
- [标题 D] — [一句话说明]
- 适合: 想理解原理、搞懂"为什么"的人

**方向 3: 🔄 对比学习**
- [标题 E] — [一句话说明]
- 适合: 想和其他技术对比、做技术选型的人

**方向 4: 🏗️ 工程实践**
- [标题 F] — [一句话说明]
- 适合: 想了解生产环境最佳实践的人

---

**请告诉我:**
1. 你更想侧重哪个方向？
2. 或者你希望覆盖哪几个方向？
3. 有没有补充的具体需求？

---

#### Phase 3: 用户选择后，进入完整收集

用户明确方向后，调用 `research-collector` 进行深度收集:

```
/research-collector "{用户选择的方向} {具体需求}"
```

### Step 3: 生成研究计划

综合用户回答，生成一份研究计划:

---

**📑 研究计划**

**主题**: {主题}
**笔记类型**: {用户选择的类型}
**目标深度**: {用户选择的深度}
**现有基础**: {用户选择的基础}

**研究方向**:
1. {方向 1}: {具体目标}
2. {方向 2}: {具体目标}
3. {方向 3}: {具体目标}

**预计产出**:
- 核心资料: {数量} 篇
- 笔记类型: {类型}
- 预计字数: {范围}

---

**确认此计划吗？** 或者你希望调整哪些方面？

[确认开始] / [调整方向]

### Step 4: 执行收集

用户确认后，调用 `research-collector` 执行完整收集流程。

```
用户: 我想学一下 Rust
```

```
AI: 没关系！我先帮你探测一下 Rust 相关的资料有哪些方向...

[派发 3 个 subagent 探测]

**方向 1: 🛠️ 实战路线** — 从零写项目（Web 服务器、CLI 工具）

你更想侧重哪个方向？或者都覆盖？
```

## 与 research-collector 的关系

```
用户输入
    ↓
research-planner（本 skill）
    ↓ 需求澄清 + 探测引导
    ↓
用户明确方向
    ↓
research-collector
    ↓ 深度收集 + 两阶段策略
    ↓
资料 + 笔记
```

## 注意事项

1. **轻量级提问**: 最多问 3 个问题，不要让用户感到繁琐
2. **探测成本低**: Phase 1 只返回标题+摘要，不消耗大量 token
3. **用户主导**: 每个阶段都给用户选择权，不强制推进
4. **允许调整**: 用户可以随时说"换个方向"或"重新来"
5. **渐进式**: 不要一次锁定所有细节，逐步明确
